<!--
Step-by-step tester page
Taken as text, as template.adp2-shell is: copy the markup into your own index.html (or take the whole page with it) and keep extending it. It is a test harness: a rail of steps, a Run step button, toasts for what each step does, and a log. A person presses the button; Claude presses the same step from outside.

What it is: a page that runs a flow one step at a time and says what it did. The steps it ships prove a whole chain: loader (the pack, seed.json and seed/, is expanded into the db by adp.js: nothing here unpacks anything), read (the collection of file docs), rights (may this viewer publish), write (ADP.unpack from adp.js publishes the docs as files, in chunks), reload, verify (fetch each file back and compare it with its doc) and clean up (delete the files again).
Steps are the extension point. kit/templates/tester.js lists them in STEPS (id, label, hint) and what each does in ACTIONS (id -> async function(ctx), it throws to fail); add one there, or pass Kit.tester.mount(root, {steps, actions, config}). ctx carries the state, log, toast, busy bar and counters. config: prefix (where files are written, default unpacked/), collection (the db collection holding the file docs, default kitfiles), ns (the db docs test/cmd and test/state, default test).
Remote: Claude writes the doc <ns>/cmd {id, action: run|back|skip|reset, step?, ts} (ArtifactData set) and the page presses it (an id seen is ignored; older than 90 s is ignored); the page reports <ns>/state {at, done, running, counts, remote, tail, t}, written only by an editor.
Data: the pack. kit/samples/tester.json holds three invented text files as db docs; pass it (or your own) to adp.py seed or adp.py new with --data and the docs ride the seed packs. The page needs the db capability, a signed-in viewer, and the artifact capability to publish.
Take also, by reference (this file is taken as text): kit/templates/tester.css and tester.js, kit/samples/tester.json, and the files named in this entry's requires. Load in the head the theme, kit/chrome.css, kit/viz/viz.css and tester.css; load before the script at the end, in the order shown.

Delete this comment when you copy the template into your page.
Provides (no global): Kit.tester.mount; .tester.
